## 1. 背景与一句话定位  
  
AI 写代码已经很普遍，开发者更多是：**打开仓库、读懂改动、做少量修正、确认后提交**。现有编辑器/IDE 为此过重：启动慢、界面满、内存高、功能密度远超「看 + 改几行」。  
  
**本产品是一个小而精的桌面应用：用来打开项目、阅读代码、做有限编辑。不是 IDE，不是 Agent 工作台。**  
  
体验目标：**安装后像启动器，打开项目后像一页纸。轻、薄、快、顺。**  
  
---  
  
## 2. 目标与非目标  
  
### 2.1 目标  
  
- 冷启动快，打开中小型仓库无明显等待  
- 界面极简且精致，默认暗色  
- 阅读代码舒适：高亮准确、滚动跟手、大文件不卡死  
- 支持必要的少量编辑并可靠保存  
- 支持按项目回顾最近打开记录  
- 单二进制分发，无浏览器内核  
  
### 2.2 非目标（明确不做）  
  
- 插件市场、主题商店、账号体系  
- 调试器、测试运行器、任务系统  
- 内置终端 / 完整 REPL  
- 实时协作、多人光标  
- 内置 AI Agent / 补全云服务（可列为远期可选，不进 MVP）  
- 远程开发、容器内编辑  
- 完整 LSP IDE（重构、Code Action、Inlay 全开）  
- 对标 VS Code / Cursor / Zed 的功能广度  
  
---  
  
## 3. 用户与场景  
  
### 3.1 目标用户  
  
- 用 AI 生成代码后，需要本地打开仓库做 review 的人  
- 偶尔改配置、文案、一行逻辑的人  
- 希望「打开看一下」而不想启动完整 IDE 的人  
  
### 3.2 核心场景  
  
1. 安装后第一次打开 → 选择文件夹打开项目    
2. 再次打开 → 从最近项目进入    
3. 在文件树中浏览结构，打开源文件阅读    
4. `快速打开` 跳到某个文件    
5. 阅读时滚动、搜索当前文件、跳到指定行    
6. 改几处内容，保存    
7. 看 Git 改动（哪些文件脏了、当前文件 diff）    
8. 收起侧栏，全屏读代码    
  
---  
  
## 4. 产品原则  
  
1. **功能能少就少**：多一个控件就要证明它每周都会被用到    
2. **阅读优先，编辑够用**：光标、选区、撤销、保存必须稳    
3. **可见即可用**：无欢迎广告、无更新新闻流、无扩展推荐    
4. **性能是功能**：卡顿等于缺陷    
5. **同一视觉语言**：启动页和工作区共用间距、圆角、字重、颜色    
6. **默认即最佳**：用户不应先配字体、主题、插件才能用    
  
---  
  
## 5. 信息架构  
  
应用只有两种顶层状态：  
  
```  
启动页  ←→  工作区  
              ├─ 侧栏：项目树  
              └─ 主区：代码  
                   └─ 可选：全屏代码（侧栏收起）  
```  
  
关闭项目回到启动页，不退出进程（除非用户关窗口）。

## 6. 功能需求  
  
优先级：P0 必须进首发，P1 首发后第一轮，P2 以后。  
  
### 6.1 启动页（P0）  
  
**描述**    
窗口打开后居中展示入口，无侧栏、无菜单墙。  
  
**必须**  
  
- 主按钮：「打开项目…」→ 系统文件夹选择器    
- 支持将文件夹拖入窗口打开    
- 「最近项目」列表，默认最多 8 条    
  - 显示：项目名（文件夹名）、完整路径（可截断）、上次打开时间    
  - 单击打开    
  - 右键或悬停：「从列表移除」（不删磁盘文件）    
- 无法访问的路径：标记失效，点击时提示并允许移除    
- 记住窗口大小与位置    
  
**不要**  
  
- 账号登录、更新日志、示例仓库广告、模板向导    
  
### 6.2 打开 / 关闭项目（P0）  
  
- 打开即该文件夹为 workspace 根目录    
- 写入最近列表（已存在则置顶并更新时间）    
- 关闭项目：回到启动页，释放文件缓冲与树缓存    
- 同时只打开一个项目（MVP 不支持多窗口多仓库；单应用单项目）    
- 忽略目录默认`.gitnode_modulestargetdistbuild.nextvendor` 等（可内置一份黑名单，P1 再做配置）  
  
### 6.3 工作区布局（P0）  
  
- 左侧项目树，默认宽约 240px，可拖拽调整（最小 ~160px，最大不超过窗口 40%）    
- 右侧代码区占满剩余空间    
- 顶栏极薄：项目名、当前文件相对路径    
- 底栏默认隐藏；保存成功可用短暂 toast，不常驻状态栏    
- 快捷键切换侧栏显隐（建议 `Cmd+B` / `Ctrl+B`）    
- 全屏代码模式：侧栏收起，代码区左右保留少量内边距（建议 24–32px）    
  
### 6.4 项目树（P0）  
  
- 懒加载展开文件夹    
- 文件 / 文件夹两种图标即可，不要图标包    
- 当前打开文件高亮    
- 单击文件：打开（已打开则聚焦）    
- 单击文件夹：展开 / 折叠    
- 键盘：上下移动、Enter 打开/展开、左折叠、右展开    
- 虚拟列表：大目录只渲染可见行    
- Git 状态（P0 最小）：已修改 / 未跟踪在文件名旁用极淡色点或左侧色条表示    
- 不在 MVP 做：拖拽移动文件、新建/删除/重命名（P1）  
  
### 6.5 打开文件与标签（P0 / P1）  
  
**P0**  
  
- 同一时间主区显示一个文件    
- `Cmd+P` / `Ctrl+P`：按文件名模糊搜索并打开（排除忽略目录）    
- 打开过的文件保留在内存，切回不丢光标（会话内）    
  
**P1**  
  
- 多标签（可选）。若做，标签要极细，可关闭；默认仍可只开单文件模式    
  
### 6.6 代码阅读（P0）  
  
- 等宽字体显示；中西文混排尽量对齐（字体策略见 UI 规范）    
- 行号    
- 当前行背景微弱高亮    
- 语法高亮（Tree-sitter），按扩展名加载 grammar    
- MVP 语言白名单：Rust、TypeScript / JavaScript、Python、Go、JSON、TOML、Markdown、YAML、HTML/CSS    
- 未知语言：纯文本，不高亮也不报错    
- 软换行可关，默认关（避免长行布局复杂）；超长行必须可横向滚动且不冻结 UI    
- 二进制 / 明显非文本：不按文本打开，提示「无法预览」    
- 大文件：先显示窗口与树，内容分区进入；单文件超过阈值（建议 5MB）可降级（不高亮或只高亮可见区）  
  
### 6.7 代码编辑（P0）  
  
必须稳定：  
  
- 插入、删除、换行、Tab（空格缩进，默认 4，可按语言 2）    
- 方向键、Home/End、PageUp/PageDown    
- 鼠标点击定位、拖拽选区    
- 复制 / 剪切 / 粘贴    
- 全选    
- 撤销 / 重做    
- 保存`Cmd+S` / `Ctrl+S`；未保存在标题或文件名旁显示点    
- 关闭文件或项目时若有未保存：对话框（保存 / 不保存 / 取消）    
  
P1：括号自动配对、行注释快捷键、多光标。    
P2：代码折叠、多选列块。  
  
### 6.8 搜索（P0 / P1）  
  
**P0**  
  
- 当前文件查找`Cmd+F`，上一个 / 下一个，高亮匹配    
- 跳转到行`Cmd+G` 或命令框输入 `:123`    
  
**P1**  
  
- 当前文件替换    
- 项目内搜索（调用 ripgrep），结果列表点击跳转    
- 大小写、正则为可选项，默认普通字符串    
  
### 6.9 Git（P0 最小 / P1 完整）  
  
**P0**  
  
- 若根目录是 git 仓库：扫描工作区状态，树节点着色    
- 无 git 则静默当普通文件夹    
  
**P1**  
  
- 当前文件 diff 视图（工作区 vs HEAD）    
- blame 可选（侧旁或悬停）    
- 不做 commit / push / 解决冲突（避免做成 Git GUI）  
  
### 6.10 设置（P1，MVP 可硬编码）  
  
MVP 允许写死：暗色主题、字号 14、行高 1.6、Tab=4。    
P1 再提供极简设置：字体、字号、Tab、是否显示侧栏、忽略规则。    
设置文件本地 JSON，不上传。  
  
### 6.11 更新与关于（P2）  
  
- 关于：版本号    
- 自动更新非必须

## 7. 交互与视觉规范  
  
### 7.1 气质  
  
安静、留白、对比克制。像阅读工具，不像仪表盘。  
  
### 7.2 结构尺寸（建议）  
  
- 网格：8px    
- 启动页窗口建议默认 880×600，工作区默认 1200×800（可记用户值）    
- 顶栏高度：36–40px    
- 树行高：24–28px    
- 代码字号：13 或 14    
- 代码行高：1.55–1.65    
- 全屏代码左右内边距：24–32px    
- 圆角：启动页卡片 12px，按钮 8px，工作区内部尽量少圆角    
  
### 7.3 颜色（暗色默认）  
  
只保留一层背景、一层表面、一条极淡分割线、一种强调色。  
  
- 窗口背景略深    
- 树与代码区几乎同色，分割线 alpha 很低    
- 选区、当前行、匹配项对比清晰但不要霓虹    
- Git：修改一种色、新增一种色，饱和度低    
  
滚动条：默认隐藏或极细，滚动时出现。  
  
### 7.4 字体  
  
- 代码：JetBrains Mono 或 Geist Mono    
- 中文回退：更纱黑体 Mono / 思源等宽    
- UI 文案可用同一等宽或稍紧的无衬线，不要多种装饰字体    
  
### 7.5 动效  
  
只允许短、功能性：  
  
- 侧栏展开/收起：120–160ms    
- Toast：淡入淡出    
- 禁止大面积弹性、视差、启动页复杂动画    
  
### 7.6 快捷键（MVP）  
  
| 操作 | macOS | Windows / Linux |  
|---|---|---|  
| 打开项目 | ⌘O | Ctrl+O |  
| 快速打开文件 | ⌘P | Ctrl+P |  
| 保存 | ⌘S | Ctrl+S |  
| 查找 | ⌘F | Ctrl+F |  
| 跳转行 | ⌘G | Ctrl+G |  
| 切换侧栏 | ⌘B | Ctrl+B |  
| 撤销 / 重做 | ⌘Z / ⇧⌘Z | Ctrl+Z / Ctrl+Y |  
| 关闭项目 | ⌘W 或菜单 | Ctrl+W |  
  
与系统文本编辑习惯冲突时，以平台惯例为准。

## 8. 非功能需求  
  
### 8.1 性能（首发验收线）  
  
在主流笔记本（8GB+、集成显卡）上：  
  
| 指标 | 目标 |  
|---|---|  
| 冷启动到启动页可点击 | ≤ 300ms（Release） |  
| 打开含 1 千～1 万文件的仓库到树可交互 | ≤ 500ms（忽略目录已排除） |  
| 打开 ≤ 1MB 源文件到可阅读 | ≤ 150ms |  
| 空闲内存（启动页） | 尽量 &amp;lt; 80MB |  
| 打开普通项目阅读时 | 尽量 &amp;lt; 150MB |  
| 滚动 | 跟随显示器刷新，无明显掉帧 |  
| 超长单行 / 数万行文件 | 不锁死 UI；可降级高亮 |  
  
UI 线程禁止做：磁盘全量扫描、全文件 parse、git status 全量阻塞、ripgrep。  
  
### 8.2 平台  
  
- P0：macOS（开发与打磨主平台，若团队从 Mac 开始）    
- P0/P1：Windows、Linux（Wayland + X11）    
- 单窗口应用    
- 高 DPI 清晰    
- 输入法：中文 IME 必须可输入（P0 在编辑场景验收）  
  
### 8.3 可靠性  
  
- 打开失败、权限不足、文件在外部被删：提示，不崩溃    
- 外部修改当前文件：P1 提示「已在磁盘变更」，MVP 可先忽略或简单提示    
- 崩溃不丢已保存文件；未保存缓冲 P2 再做恢复    
  
### 8.4 安全与隐私  
  
- 无账号、默认无网络（检查更新除外，且须可关）    
- 不上传代码    
- 最近项目只存本地路径    
  
### 8.5 无障碍（P1）  
  
- 系统缩放不糊    
- 键盘可完成打开项目、打开文件、保存、关项目    
- 对比度达到可读，不强求首发完整读屏  
  
### 8.6 国际化  
  
- MVP：界面中文或中英择一，代码内容按文件原样    
- 路径、日期按系统 locale

## 9. 技术架构约束  
  
### 9.1 技术栈  
  
| 层 | 选择 |  
|---|---|  
| 语言 | Rust |  
| UI | GPUI + `gpui_platform`（版本钉死） |  
| 可选组件 | gpui-component（按钮/列表等壳层） |  
| 文本缓冲 | ropey（或先 gap buffer，需可替换） |  
| 高亮 | Tree-sitter，仅处理可见行 + 增量 |  
| 项目搜索 | ripgrep（系统或内嵌二进制） |  
| Git | libgit2 或调用 git CLI |  
| 最近项目 | 本地 JSON |  
  
禁止：Electron、Tauri/WebView、把 Zed 整仓当依赖。  
  
### 9.2 模块  
  
- `app`：进程、窗口、启动页/工作区切换    
- `workspace`：根路径、树、打开缓冲集合    
- `core`：buffer、光标、选区、undo、命令    
- `editor`：GPUI 代码视口（虚拟行、高亮 spans、输入）    
- `git` / `search`：后台任务，结果回 UI    
- `theme`：颜色与尺寸常量    
  
硬规则：UI 只渲染快照；变更走命令。  
  
### 9.3 GPUI 使用约定  
  
- 文件树、搜索结果、代码行一律虚拟列表`uniform_list` 或同等机制）    
- 钉 GPUI 版本，升级单独排期    
- 不复制 Zed 的 `editorlanguage` 整套 crate

## 10. 版本划分  
  
### MVP（v0.1）  
  
启动页 + 最近项目 + 打开文件夹 + 树 + 单文件阅读 + Tree-sitter 白名单高亮 + 基本编辑与保存 + 文件内查找 + 快速打开 + 侧栏显隐 + Git 脏标记。  
  
### v0.2  
  
项目搜索、替换、多标签或预览栈、文件增删改名、diff、设置、Windows/Linux 打磨、IME 强化。  
  
### 以后视需求  
  
blame、只读 LSP（hover / 跳转定义）、会话恢复、多仓库窗口。  
  
---  
  
## 11. 验收标准（MVP）  
  
1. 新用户能在 10 秒内打开一个本地项目并看到代码    
2. 最近项目第二次进入无需再选文件夹    
3. 在 2000+ 文件的常见前端或 Rust 仓库中，树滚动与打开文件流畅    
4. 修改并保存后磁盘内容正确，撤销可回到保存前    
5. 关闭未保存文件必有确认    
6. 侧栏可一键消失，代码区全幅阅读    
7. Release 构建下启动页与工作区无明显卡顿、无崩溃    
8. 界面无多余入口：无插件、无 AI、无终端    
  
---  
  
## 12. 成功指标（定性 + 可后期量化）  
  
- 用户评价接近：「像打开预览器，但能改」    
- 对比 VS Code 打开同一仓库：启动与内存明显更低    
- 完成一次「打开 → 读 → 改一行 → 保存」无需配置

## 13. 风险  
  
| 风险 | 影响 | 缓解 |  
|---|---|---|  
| GPUI API 不稳定 | 升级成本高 | 钉版本；壳与 core 分离 |  
| 自研编辑器细节多（IME、选区、超长行） | 排期膨胀 | MVP 编辑范围锁死；先做稳阅读 |  
| 中英混排与字体 | 观感差 | 第一天选定字体组合 |  
| 范围蔓延成迷你 IDE | 失去「轻」 | 非目标清单作为评审门槛 |

## 15. 附录：MVP 范围一句话  
  
**一个 GPUI 桌面窗口：先选项目，再在薄布局里读代码、改几处、存盘；树、高亮、查找、快速打开、Git 脏标记齐全，除此之外全部推迟。**
