# Folio v0.4

2026-09-12。v0.3 功能面已经收束。这一轮只补**阅读式 review** 还卡手的地方：AI 写完之后，人要看见改了哪些文件、对照着读，而不是自己在树上找绿点。

原则仍是需求文档第 4 节：功能能少就少；阅读优先。写操作（commit / push / 冲突）继续交给终端，不在 Folio 里做。

## 为什么要并排 diff

v0.2 写成「只做统一 diff」，是当时为了少一块布局，不是 review 不需要左右对照。统一 diff 适合扫一行增删；并排是读一次改动时更自然的视图：旧左新右，删和加对得上。窄窗口仍可用统一；宽了就切并排。两种都是只读。

## 不做

- stage / unstage、写 commit、push / pull / fetch
- 建分支、checkout、stash、rebase、冲突编辑器
- GitHub / GitLab PR 评论
- LSP、AI、插件

## 做

### 1. 改动列表

菜单条上一项（Lucide `git-compare`）。侧栏切到当前项目的 dirty / untracked 文件，按路径排。点开就是那个文件的 diff。空列表一句 `No changes`。`⌘B` 仍管侧栏显隐，不换模式。

### 2. 并排 / 统一

改动视图标题栏切换 Unified / Split。默认 Unified，和现在一样。Split 把同一份 hunk 画成两列：替换行左右对齐，纯增左空、纯删右空。

### 3. hunk 与文件跳转

`F7` / `⇧F7` 上一个 / 下一个 hunk。标题栏也有按钮。下一个 / 上一个改动文件走列表的 `↑` `↓` `Enter`，以及标题栏上的文件按钮。

### 4. 对比基准

默认仍是工作区对 `HEAD`（还没提交的）。可切到仓库的主分支（`origin/HEAD` → `main` → `master`），看这一支相对主干。仍是 `git diff`，只读。

## 验收

- 改两个文件，从列表连续打开，不必回树找
- 同一处替换在 Split 下左右对齐
- `F7` 落到下一个 hunk
- 切到主分支后，已提交但未合入主干的改动也看得见
- 没有 staging、没有提交框

## 停手

列表、对照、跳转够用就停。不要接着做提交。
